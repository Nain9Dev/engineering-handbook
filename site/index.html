Five engineering tenets

Everything else in the handbook follows from these.

1

Determinism over heuristics

Systems yield reproducible, verifiable outcomes. Ambiguous heuristics and uncalibrated thresholds are not accepted.

2

Spec-driven engineering

Code is the last artifact of a pipeline: numbered documentation phases, explicit acceptance criteria and recorded decisions come first.

3

Test-first verification

A feature or fix without an automated test does not exist. Tests bracket every structural refactor.

4

Clean layering

Domain logic stays decoupled from databases, frameworks and transport. Dependencies flow inward.

5

Zero-cost production footprint

Portfolio applications and demos run at no recurring infrastructure cost, using static builds, free tiers and public automation.

Who does each task

Every task in a repository roadmap carries one of three ownership tags, so it is clear what can run without a person.

[A] Autonomous

Runs end to end in CI or with an AI assistant, with no manual step.

[M] Mutual

Needs a human action to close: authorisation, an account or a key.

[H] Human only

Reserved for the principal architect: business strategy, client agreements and final approvals.

Isolation rule: private and client code stays separate. No business rules, credentials or internal schemas move into public repositories, and public material is scanned for confidential names before it is published.
